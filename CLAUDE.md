# BoplMods — Claude guide

BepInEx 5 + Harmony mods for **Bopl Battle** (Unity 2022.3.60, Mono backend, Steam app 1686940), distributed through Thunderstore (Thunderstore Mod Manager / r2modman).

## Layout

```
Directory.Build.props     shared settings: netstandard2.1, BepInEx/Harmony NuGet refs, game DLL refs, paths
Directory.Build.targets   DeployToProfile (after every build) + PackThunderstore target (tcli)
Directory.Build.user.props  (optional, git-ignored) per-machine overrides; see *.example
BoplMods.sln
mods/<ModName>/           one project per mod: .csproj, Plugin.cs, *Patches.cs, thunderstore.toml, README.md, CHANGELOG.md, icon.png
decompiled/Assembly-CSharp/  ILSpy output of the game (git-ignored, reference only; never ship or commit)
tools/                    dnSpyEx (GUI decompiler/debugger), UnityExplorer (runtime inspector plugin)
dist/                     Thunderstore zips produced by PackThunderstore
```

## Commands

```bash
dotnet build mods/<Mod> -c Release                          # build + copy DLL into the Default mod manager profile
dotnet build mods/<Mod> -c Release -t:PackThunderstore      # also build dist/<Team>-<Mod>-<Version>.zip
dotnet build -c Release -p:DeployToProfile=false            # build all, no deploy
build-all.cmd [Mod ...]                                     # build + pack every mod (or the named ones) into dist/, no deploy
```

- Build single projects (`mods/<Mod>/<Mod>.csproj`). CaliGameModes' build also builds and deploys CustomRules and CaliSkills.
- Deploy target: `%APPDATA%\Thunderstore Mod Manager\DataFolder\BoplBattle\profiles\Default\BepInEx\plugins\<Team>-<Mod>-dev\`
- Runtime log: `<profile>\BepInEx\LogOutput.log` — check it after launching to confirm the plugin loaded and patches didn't throw.
- Launching modded from CLI (what the mod manager does):
  `steam.exe -applaunch 1686940 --doorstop-enabled true --doorstop-target-assembly "<profile>/BepInEx/core/BepInEx.Preloader.dll"`
- Re-decompile after a game update: `ilspycmd -p -o decompiled/Assembly-CSharp -r "<game>/BoplBattle_Data/Managed" "<game>/BoplBattle_Data/Managed/Assembly-CSharp.dll"` (ilspycmd lives in `%USERPROFILE%\.dotnet\tools`, which may not be on Git Bash PATH).

## Conventions

- Version lives only in the `.csproj` `<Version>`; namespace (team) only in `ThunderstoreTeam` in Directory.Build.props. `PackThunderstore` passes both to tcli, overriding `thunderstore.toml`.
- Plugin GUID: `com.boplmods.<modname>` via `<BepInExPluginGuid>`; code uses the generated `MyPluginInfo`.
- `Assembly-CSharp` is referenced with `Publicize="true"`: private game members can be used directly (`__instance.isInAbility`) — no `Traverse`/reflection needed. Harmony targets via `nameof(...)` still work.
- **Never `UnpatchSelf()` in a plugin's `OnDestroy`.** Bopl Battle destroys the BepInEx manager GameObject (all plugin MonoBehaviours) before the main menu, so it would silently remove every patch. Plugin `Update`/coroutines don't survive either; for per-frame logic, patch game methods or create your own `DontDestroyOnLoad` GameObject.
- Prefer Prefix/Postfix over Transpilers; keep per-object mod state in `ConditionalWeakTable<TComponent, TState>`, not static fields shared between players.
- Each mod's README is the Thunderstore page; keep it user-facing.

## Bopl Battle specifics (important)

- **Deterministic lockstep netcode, no rollback.** Gameplay runs in `UpdateSim(Fix dt)` / `LateUpdateSim` on `MonoUpdatable`s, using `BoplFixedMath.Fix`/`Vec2`, not floats or `Time.deltaTime`. Gameplay mods must:
  - only depend on simulated state + synced inputs (`Player.jumpButton_PressedThisFrame()`, `Player.InputVector()`, `AbilityButtonIsDown(i)`),
  - use `Fix` math, never `UnityEngine.Random`/`System.Random`/floats/wall-clock in sim logic,
  - be installed with identical config by every player in the lobby. Cosmetic/UI-only mods are client-side safe.
- Key classes: `SlimeController` (player state machine; `OldUpdate` handles input/abilities/jump), `PlayerPhysics` (`Jump()`, `IsGrounded()`, gravity, `jumpStrength`), `PlayerBody` (`position`, `selfImposedVelocity`, `externalVelocity`), `PlayerHandler.Get().GetPlayer(id)`, `Player` (inputs, scale, stats), `GameTime`, `Updater`, `AudioManager.Get().Play(...)`, ability classes (`Roll`, `Beam`, `MeteorSmash`, ...).
- Unity log appears in BepInEx log as `[Info : Unity Log]`.
- Keyboard+mouse gameplay bindings (sharedassets1.assets): Jump = Space, Ability0 = left mouse, Ability1 = right mouse, Ability2 = middle mouse (or mouse back/forward), aim = mouse position.
- Abilities: `docs/ABILITIES.md`. The list is the `abilityIcons` NamedSpriteList asset (shared by `AbilityGrid`, `SteamManager.instance`, `AchievementHandler`, `RandomAbility`); index = ability id, entry = name + icon + prefab (`associatedGameObject`) + `isOffensiveAbility`. Players/slimes: `CharacterSelectHandler.TryStartGame_inner` builds `Player`s, `GameSessionHandler.SpawnPlayers` instantiates `PlayerPrefab` per player.
- Missing sounds (`AudioManager.Play`) and translations (`LocalizationTable.GetText`) only log warnings.

## Mods

- `mods/CaliSkills` — the user's ability pack. `Core/Skill.cs` (base class: name, icon, prefab), `Core/SkillRegistry.cs` (appends every registered skill to the `abilityIcons` list, same patches as SpawnBot; prefabs live under an inactive DontDestroyOnLoad root), `Core/SpriteFactory.cs` (runtime sprites). Add a skill: new folder under `Abilities/`, a `Skill` subclass, `SkillRegistry.Add(...)` in `Plugin.Awake`. Tuning values live in a `<Skill>Settings.cs` static class per skill.
  - Pinball (`Abilities/Pinball`): clone of the Grenade ability prefab (`ThrowItem2`: hold in hand, aim, throw; `Ability.Cooldown` set, `minThrowForce`/`maxThrowForce` = 0, `ItemPrefab` swapped, hand "dummy" (child 1) sprite replaced). Ball = copy of the grenade item: keeps `Item` + `Grenade` (ThrowItem2 needs them), `IGrenadeDetonation` components removed and `timedExplosion` off, children/SpriteAnimator removed, grenade's "item" layer KEPT (abilities recognise items by layer: Duplicator, Black hole, Gust achievement, KillZone, bounds cleanup), bounciness = `BouncePower` (restitution, `1 + max` of both bodies in PhysTools) / no friction, runtime ball sprite. `PinballBall` (also a no-op `IGrenadeDetonation`): while held (`!grenade.hasBeenThrown`) sets `Scale` from the thrower's charge (`Clamp01((hasInputtedFire ? FireInputTimeStamp : timePassed) * ThrowForceGainSpeed)`, same as the aim indicator); on release sets velocity = `thrower.dir` × charge-scaled speed; lifetime counted from the throw (fixed, not charge-scaled); per-player hit cooldown; owner = `Item.OwnerId`, can hurt owner = `Grenade.DetonatesOnOwner`. Speed, size and knockback scale linearly from `...AtMinCharge` to the full values. State fields (`_thrown`, `_charge`, `_baseScale`, `_ageSinceThrow`) are `[SerializeField]` so the Duplicator's copies (`ShootDuplicator.DuplicateObject` = Instantiate of the live object, then `Grenade.Initialize(null)` + `hasBeenThrown = false`) don't re-launch and keep their fan-out velocity. Player hits: `PinballBall.OnCollide` (`ICollisionCallback` on its circle, same rules as `GrenadeExplode.OnCollide`: owner immunity via `DetonatesOnOwner`, Magnet-gun holder immunity; slimes with `!hasSpawned` (spawn/revive animation, which ends by calling `Spawn()`; a ragdoll would cancel it and freeze them) are ignored) → `PinballKnock` detaches grounded players (impulse reflected/biased away from the attached surface's normal, else the landing raycast re-attaches them) then ragdolls the slime (`ApplyRagDoll`, like the Magnet gun throw) or pushes ability forms; the ball is reflected. "item" isn't a lethal layer in `PlayerCollision`, so no kill patch is needed.
  - Embedded assets: files in `mods/CaliSkills/Assets` are `EmbeddedResource`s named `CaliSkills.Assets.<file>`; `Core/EmbeddedAssets.cs` turns a PNG into a round ability icon at a vanilla icon's exact pixel size + pixels-per-unit (`LoadRoundIconLike`; the character select UI draws icons at their pixel size, in-match indicators at world size, so both must match the reference; needs ImageConversionModule) and a 16-bit PCM WAV as an AudioClip (`LoadWav`; convert 24-bit/extensible WAVs first); `SoundPlayer.Play` plays it on a DontDestroyOnLoad AudioSource at `AudioManager` master × sfx volume (client-side only).
  - Omae wa mo shindeiru (`Abilities/Omae`; icon `Assets/omae_icon.png`, sound `Assets/omae_sound.wav` played by `OmaePoke` when it marks someone): also a Grenade (`ThrowItem2`) clone: no throw force/recoil, aim indicator (child 0) and hand dummy (child 1) renderers hidden, `ItemPrefab` = invisible tiny `OmaeHandItem` (stripped grenade; destroys itself once `hasBeenThrown`, so interrupted throws leave nothing). `OmaeCone` (on the prefab; unparented cone GameObject drawn in LateUpdate from `thrower.dir`/`body.position`, sprite = `OmaeSkill.ConeSprite`, radius 1 unit, rebuilt when `HitboxAngle` changes) doubles as the marker for `OmaePoke` = postfix on `ThrowItem2.Fire` (sim): every other player whose `PlayerCollision` body (circle of `physics.radius`) touches the cone (`HitboxSize` × owner scale, `HitboxAngle`, Fix math) and is in line of sight (`DetPhysics.RaycastToClosestRoundedRect` to its center or either side at 0.8 × radius; any clear ray counts) is marked once. `OmaeMarks` (scene MonoUpdatable created on first mark → reset every level; `SortedDictionary` by player id): countdown with `GameTime.FixedDeltaTime`, reduction on re-poke, mark dropped when the player isn't alive, at 0 `killPlayer(markerId, spawnEffect, Squished)` on every active body (sorted by position; retried next tick if none died, e.g. invulnerable). Flash = child SpriteRenderer under each body's sprite renderer (slime: `SlimeController.spriteRen`, a child tagged "PlayerSprite", NOT on the root; form: `Ability.spriteRen`) copying its sprite with a "GUI/Text Shader" material (solid silhouette), flash rate lerps `FlashesPerSecond`→`FlashesPerSecondAtEnd` and strength 0.45→0.95 as the mark runs out; alpha × target alpha (invisible stays invisible); red vs white decided from the player material (color props/name, logged once).
  - Run (`Abilities/Run`): plain GameObject prefab (FixTransform + `RunAbility : AbilityMonoBehaviour`, instant, like SpawnBot). `EnterAbility` activates its GameObject (ability objects spawn inactive and `Updater` skips inactive updatables, like `InstantAbility`), multiplies the caster's `PlayerPhysics` maxSpeed/accel/airAccel (restored exactly on stop); while the button is held the slot's `abilityCooldownTimers` is pinned to 0 (cooldown starts on release); prefix on `SlimeController.EnterAbility` stops it when another slot is used (then needs a release: `IsCastable`).
  - Nothing Personal Kid (`Abilities/NothingPersonal`): instant `AbilityMonoBehaviour` like Run. On use: target = alive enemy `PlayerCollision` body furthest away (sorted, deterministic), on use the caster departs (hidden: sprite off, `playerPhysics.enabled`/`body.simulated` off, `suppressInput`, immune; smoke + Teleport particles: `onCastParticlePrefabSmall` at origin, `onCastParticlePrefab` at destination, two `betweenPortalsParticlePrefab` beams set up like `Teleport.CastAbility`) and arrives after `TravelTime` 0.1 s at the marker (recomputed, it follows the target): behind = opposite to the target slime's facing (`isFacingRight` × platform `forwardsDirection`, or toward the caster for ability forms), lifted `BehindLift` along the platform normal, clamped to camera bounds; caster un-grounded/un-roped, zero velocity, faces the target. Then immune: `PlayerCollision.SetInvulnerable(true, 1<<10)` + hurtbox off for `ImmunityDuration`, and other abilities blocked via a postfix on `SlimeController.isAbilityCastable` for `AbilityLockDuration`. Visuals (`NothingPersonalVisuals`, built in CreatePrefab): marker = copy of `Teleport.tpiPrefab` stripped to Transform/Renderer/ParticleSystem (scalingMode Hierarchy, tinted with `_ShadowColor`); smoke = `SmokeGrenadeExplode2.Smoke` (FlammableSmoke) `animData` "enter"+"loop" frames on a plain SpriteRenderer that fades (`SmokePuff`). Needs `UnityEngine.ParticleSystemModule`.
  - Runtime textures/sprites/AudioClips get `HideFlags.DontUnloadUnusedAsset`: `Resources.UnloadUnusedAssets` on scene loads destroys anything only referenced natively (e.g. a GUIStyle background).
  - Skill settings = CustomRules ability stats (`Core/CustomRulesStats.cs`): CustomRules is a soft `[BepInDependency]` (ProjectReference `Private=false`); if `Chainloader.PluginInfos` has it, every skill's `SettingsType` is passed to `CustomRules.Core.AbilityStats.Register(name, type, skill.OnSettingsChanged)` from a separate NoInlining method (CustomRules types never load without it). Without CustomRules the defaults from code are used. The old dev editor (right-click in the grid, local only) was removed. New skills: give them a `<Skill>Settings` static class with `[Description]`s and override `SettingsType`.
  - `Core/AbilityGridScroll.cs`: patches `AbilityGrid.Awake/Init/Update` to scroll the grid vertically when it's taller than the screen (keeps vanilla layout, shifts entries' localPosition, hides entries outside the window, follows selection, mouse wheel). Needs `UnityEngine.UIModule` + `Unity.InputSystem` references (in CaliSkills.csproj). Vanilla reference: arrow radius 0.61, gravity 1, `ArrowSpeed` 15 (×1–5 by charge); Magnet gun `FireRagdollForce` 60, `fireRagdollDuration` 0.3.
- `mods/CustomRules` — host-set match rules. `Core/Rule.cs` (local value = BepInEx config entry, active value = in effect this match, read by gameplay code: `ActiveFix`/`ActiveBool`/`IsOn`), `Core/RuleRegistry.cs` (public API for other mods: `AddFloat/AddInt/AddBool(..., parent, section)` — a child of a bool rule is its sub menu (and inherits its section); `AddSection(title, tint)` = a mod's group, drawn after the basic rules with a gap in a tinted `GUI.skin.box` under a bold title (needs TextRenderingModule for `FontStyle`); `AddSyncedValue(key, readLocal, applyActive)` = hidden value sent with the rules; `RulesActivated` event; internal `AddHidden` = a rule with `Hidden` set: no row in the Rules tab but saved/synced/in profiles like any rule). Ability stats (`Core/AbilityStats.cs`, public API `AbilityStats.Register(abilityName, settingsType, onChanged)`): each public static float/int/bool field = a hidden rule `Stat.<ability letters/digits>.<field>` in config section [AbilityStats], default = field value at registration; on `RulesActivated` the fields are set to the active values and `onChanged` runs. Disabled abilities = hidden Choice rule `DisabledAbilities` ("a|b|c"), part of `AbilityRules.Allowed` (like the offensive filters: greyed, unpickable, un-ready, start blocked, Random re-draws; Random itself can be disabled). `UI/RulesMenu.Abilities.cs`: "Abilities" row in the Rules tab → ModalWindow grid of every ability (right/left-click = stats window for abilities with registered stats, middle-click = toggle disabled; IMGUI `Event.current` MouseDown with `button` on a `GUILayoutUtility.GetRect`), edits pending in `_texts` until Apply like other rules. `UI/AbilityBadges.cs`: generated yellow ring / red no-sign textures (the abilities window draws a yellow button border instead of the ring); child `Image`s (raycastTarget off, anchors around the icon) on `AbilityGridEntry.iconRenderer` and `SelectAbility.abilityIconRenderer` for lobby values; middle-click in the grid (`AbilityGrid.Update` postfix, entry under the mouse via `RectTransformUtility`) toggles the local rule at once and broadcasts if host (guests can't). Needs `UnityEngine.UIModule`. `Core/RulesSync.cs`: local games activate this machine's values in `CharacterSelectHandler.TryStartGame_inner`; online the host sends a custom P2P packet (`"CRULES1\nkey=value..."`, ≥128 bytes: vanilla packets are told apart by size in `SteamSocket.OnMessage`, unknown sizes are ignored) on Apply, on `SteamConnection.OnConnected` and before `SteamManager.HostGame`/`HostNextLevel` (same reliable connection → arrives before the 105-byte start request); every machine activates in `CharacterSelectHandler_online.ForceStartGame` (host: own values, clients: host's). Game mode profiles: `Core/RuleProfiles.cs` (files `BepInEx/config/CustomRules.Profiles/<name>.rules`, `key=value` lines of local values; loaded name in config [Profiles] Active; the first load backs up the current rules to `_before_profile.txt`, Unload restores them; missing/invalid keys → default; applying broadcasts if host), UI in `UI/RulesMenu.Profiles.cs` (partial class; Profiles tab + "Save to profile" line on the Rules tab). `UI/RulesMenu.cs`: IMGUI "Custom rules" button (top-left) in scenes `CharacterSelect`/`ChSelect_online`, read-only for online clients; while open (and the closing frame) the character-select scripts that read the keyboard are skipped (incl. `CharacterSelectHandler_online.Update`, which leaves the lobby on Esc) and EventSystems disabled. Rules (`Rules/`): cooldown = postfix on `Ability.GetCooldown`/`InstantAbility.GetCooldown` (skip Invisibility's 10000 sentinel); size (3 = normal) = after `GameSessionHandler.SpawnPlayers`, |size-3| Growth/Shrink ray `ScaleChanger`s per slime (prefab found via `ShootScaleChange` in the ability list, sign of `PlayerMultiplier`), vanilla 0.3–3 clamp kept; gravity = `PlayerPhysics.AddGravityFactor` (temporary `gravity_modifier` scale) + `DetPhysics.gravityAccel` per level; speed = `PlayerPhysics.Move/MachoMove/AirealMovement` (temporary maxSpeed/accel/airAccel scale, outermost call only); invisibility = postfix `Player.UpdatePlayer` keeps `isInvisible` and the fade timer. No ability pickups = skip `AbilitySpawner.UpdateSim` + `SlimeController.DropAbilities`; ability spawning time = same prefix divides `simDeltaTime` (only advances the spawner's clock vs `SpawnDelay` 40); ability cap per round = same prefix sets `MaxSpawns` (vanilla 3) every tick. Player bouncing (`Rules/PlayerBouncingRule.cs`, slimes only, not ability forms): a `PlayerBouncer` MonoUpdatable per level (added after `SpawnPlayers`) resolves every overlapping slime pair each tick (sorted by playerNumber + position; equal-mass impulse with separation speed ≥ max(approach × power, 15 × power); grounded slimes slide via `groundedSpeed` or `UnGround` + `selfImposedVelocity` when pushed off; airborne ones are un-overlapped); "bounce on everything" = prefix `PlayerPhysics.CollideWithGround` for slimes: place at the would-be attach point + 0.05 along `currentNormal`, reflect self-imposed + external velocity with restitution `1 + power`; each platform bounce gives one jump charge (`BounceJumpPatch`, ConditionalWeakTable, postfix `SlimeController.OldUpdate`: jump pressed in the air → upright `PlayerPhysics.Jump()`, same guards as the air jumps; priority High so it runs before `AirJumpsRule`, which skips when `jumpedThisFrame`). Triple jump (`Rules/AirJumpsRule.cs`, formerly the TripleJump mod, removed from the repo; it's in git history): postfix `SlimeController.OldUpdate`, airborne the whole frame + jump pressed → upright `PlayerPhysics.Jump()`, up to `TripleJump.AirJumps` per landing; reset on landing, Spawn/ReSpawn and platform bounces. Conflicts with `thepro-DoubleJump`. Ability rules (`Rules/AbilityRules.cs`): No/Only offensive (`MakeExclusive`) act in character select (`Rules/AbilityFilterLobby.cs`, using lobby values `RulesSync.LobbyText`/`LobbyBool` = host's for online guests): grid entries greyed (`AbilityGridEntry.iconRenderer.color` in an `AbilityGrid.Update` postfix), `CharacterSelectBox.CloseAbilityGrid` refuses them, `SelectAbility.Move` skips them, a slot still holding one is greyed and blocks `CharacterSelectBox.OnEnterReady`, un-readies the box in a `CharacterSelectBox.Update` postfix (`CancelLocalReady` if trueReady, then `OnEnterSelect`), and blocks `CharacterSelectHandler.TryStartGame_inner` / the host's `CharacterSelectHandler_online.TryStartGame` (remote picks = `SteamConnection.lobby_ability1-3`); no replacement at round start. In the match they re-draw disallowed results in a postfix on both `RandomAbility.GetRandomAbilityPrefab` overloads (seeded `Updater.RandomInt`, also covers pickups); "Preselect abilities" section = 3 `AddChoice` rules (ability names from `SteamManager.instance.abilityIcons`, "" = player's choice) forced per slot in the same prefix (wins over the filters). Choice rules: `RuleType.Choice`, string config entry, drawn as ◀ name ▶, or with an `icon` provider (name → Sprite) as ◀ [icon] ▶ where clicking the icon opens a grid picker (`UI/RulesMenu.Choice.cs`; drawn as its own ModalWindow in place of the rules window since IMGUI allows one modal; atlas sprites drawn via `textureRect` UVs). Bouncing: closing speed ≥ `DetachImpactSpeed` 18 knocks grounded slimes off (into-platform push reflected). Cooldown rule: Ability/InstantAbility via attributes; other `AbilityMonoBehaviour` subclasses (modded) patched once at the first character select (`CooldownRule.PatchModdedAbilities`), since their DLLs may load after CustomRules. The rule frame GUIStyle rebuilds if its texture was unloaded. Infinite round = skip `GameSessionHandler.ActivateSuddenDeath(true)` (sudden death after `TimeBeforeSuddenDeath` 120 s drops platforms via `SuddenDeathInProgress`).
- `mods/CaliGameModes` — depends on CustomRules + CaliSkills (ProjectReferences, `Private=false`; CaliSkills has `InternalsVisibleTo("CaliGameModes")`). Adds rules to the CustomRules menu, in its own section (`Plugin.Section`, light blue). Pinball mode (`Modes/PinballMode.cs`): rule `PinballMode` + child `PinballMode.SpawnInterval`; the Pinball's settings come from the host as CustomRules ability stats (registered by CaliSkills); a `PinballSpawner` MonoUpdatable is added after every `GameSessionHandler.SpawnPlayers` and calls `PinballSkill.SpawnBall` (owner -1, full charge, `PinballBall.LaunchStandalone`) from a random side (inset 25% of the half-width, 25–55% of the height, aimed 27–63° up towards the center; 1 in 4 from the sky at 90% height, up to ±60° from straight down; speed × random 1.1–1.4 via `PinballBall._speedMultiplier`, serialized so Duplicator copies keep it) using `Updater.RandomInt/RandomFix`.
- `mods/SpawnBot` — dev tool. Adds a custom ability by appending a `NamedSprite` ("SpawnBot", runtime-drawn icon, inactive template GameObject with `FixTransform` + `SpawnBotAbility : AbilityMonoBehaviour`) to the `abilityIcons` NamedSpriteList (prefix on `AbilityGrid.Awake`, `CharacterSelectHandler.TryStartGame_inner`); excluded from `RandomAbility.GetRandomAbilityPrefab`. Casting it adds a bot `Player` (new id, unused team) to `PlayerHandler` and spawns its slime like `PlayerCollision.SpawnAbilityLessClone`. Bots are hidden from the player list during `GameSessionHandler.UpdateSim`/`EndGameImmediately` (win logic) and removed in `Updater.PreLevelLoad`. Local games only.
